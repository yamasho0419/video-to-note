# 執筆ルール(全チャンネル共通)

動画を note 記事にするときの、唯一のルール集。youtube-to-note / note-critique / note-eye-fix も
ここを参照する。チャンネル固有のこと(定型の自己紹介、文体の型、一人称、フッター、CTA の方針、
用語集)は `channels/{チャンネル}/voice.md`・`footer.md`・`glossary.md` に書いてあり、
**このファイルと食い違ったらチャンネル側を優先する**。

記号(F1, S6 など)は添削の記録から抜き出した失敗パターンの番号。lint の WARN と対応している。
【機械】が付いた項目は `scripts/lint_article.py` が検出する。

目次
1. 大原則: 変えてよいのは表現と構成だけ
2. 事実の扱い(F1〜F9)
3. 記事の型(序論・本論・結び)
4. 見出しと構成(S1〜S12)
5. 読みやすさ(R1〜R7)
6. 画像(I1〜I7)
7. 題名
8. 書き終えたら(自己チェック)

---

## 1. 大原則: 変えてよいのは表現と構成だけ

目的は動画の要約ではなく、話者が自分で書いた note として自然に読める記事に再構成すること。
読者は「この人が書いた記事」として読む。だから、話者が言っていないことが1つでも混ざると、
記事全体の信用が落ちる。

変えてよいもの:
- 話し言葉→書き言葉、会話形式→一人称の文章
- 話題の順番、同じテーマの発言を1か所に集めること、重複の整理
- 見出し・段落分け・箇条書き・太字
- 「えー」「まあ」など意味を持たない言葉を削ること

変えてはいけないもの:
- 話者が言っていない事実・経験・感情・価値観・結論を足すこと
- 実績・数字・肩書きの創作、丸め、換算
- 意味が変わる要約、誇張、営業効果を上げるための実績・メリットの追加
- 動画の時点の情報を、今の情報に書き換えること(フォロワー数・実績の件数・肩書きは動画のまま)

例: 「大学生のときにプログラミングに興味を持って、勉強を始めました」→「大学生のときにプログラミングに興味を持ち、そこから勉強を始めました」は適切。
「大学生のころは将来に不安を感じていて、その不安を解消するために〜」のように、語っていない動機を足すのは禁止。

質問の扱い: 「なぜこの仕事を始めたんですか？」への回答は、質問を残さず「## この仕事を始めたきっかけ」のような
見出しにして、本人が語った内容を一人称の文章にする。

動画特有の形式は持ち込まない:
- 「動画では〜と話しています」「○分○秒で」「次に〜について聞かれました」
- 「Aさん」「Bさん」の会話形式、質問と回答のやり取りをそのまま並べる形
- 字幕を時系列に並べただけの文章
- 動画の挨拶(「皆さんこんにちは」「今日のテーマは」)→「この記事のテーマは〜」にする【機械 S9】

情報源の優先順位: 本人の発言 → テロップ・画面 → 概要欄 → ユーザーが明示した情報。
情報源同士が食い違うときは、時点の違いか確かめる。確かめられなければ推測で統合しない。

## 2. 事実の扱い

ファクトチェックは別エージェントが行う(`fact_check.md`)。それでも、ここに挙げる失敗は書く段階で防ぐ。
過去の添削で何度も直したものだけを集めてある。

- **F1 一般化・頻度化しない** 聞き手がその場でした1回の質問を「こんな質問をいただくことがあります」
  「よく聞かれます」と書かない。1人の発言を「〜という方は多いです」「こんな声を聞きます」にしない。
  質問から入るときは「今回は、この質問にお答えします」で受ける。話者が自分で「多い」「よく」と言ったときだけ使う【機械】
- **F2 確度を変えない** 「〜と思います」を断定にしない。逆に断定を「〜と思います」に弱めない。
  「可能性がある」を「可能性が高い」に、「確保したい」(意図)を「確保しました」(完了)にしない。
  「一切」「必ず」「はず」を足さない。話者があいまいに言った時期・数字(「去年の夏くらいかな」「たぶん3割くらい」)は、
  あいまいなまま書く(「〜だったと思います」「3割くらい」)
- **F3 字幕に無い語を補わない** 性別・家族構成・年齢(女性、夫婦、同い年)、
  具体的な手段や種類(「電車で」「無料版で」)、副詞(すぐに)、感情語(楽しかった)、相づち・同意(「私も同じ考えです」)、
  概算の実績(「100件以上」)は、字幕かテロップに無ければ書かない
- **F4 発言者を取り違えない(重大な誤りになりやすい)** 対談・聞き手ありの動画では、エピソードと意見ごとに
  話者を字幕で確かめる。聞き手の自分語り(「僕は毎朝5時に起きています」)を話者の経験にしない。
  ゲストの意見を地の文で話者の意見にしない。帰属は「〜さんは〜と話していました。私もそう思います」の形で示す。
  話者が問いかけて聞き手が答え、話者が「そう」と認めた発言(「何が一番大事だと思う?」→「続けることですか」→「そう」)は、
  話者の考えとして地の文に書いてよい。ただし言葉そのものは聞き手のものなので、鉤括弧で引くなら
  「〜さんに聞くと『続けること』という答えで、まさにそのとおりです」のように答えた人を示す
- **F5 省略で意味を変えない** 条件・限定・但し書き(「この価格では」「初心者のうちは」「〜の場合」)を落とさない
- **F6 「別の記事」は実在を確かめてから** 動画が「別の動画で解説」と言っていても、
  該当する記事が管理表にあると確かめられたときだけ「別の記事で解説しています」と書く。無ければ書かない【機械】
- **F7 引用を合成しない** 鉤括弧の中は、字幕の一続きの発言だけにする
- **F8 ASR の誤変換を写さない** 固有名詞・数字・専門用語はテロップを切り出して確かめる。
  チャンネルの `glossary.md` にある表記を正とする。名前の誤記は lint が検出する【機械】
- **F9 動画の中で食い違う数字は統合しない** 片方だけ残すか、`human_review` に回す

締めの呼びかけは例外的に、**意味を言い直すだけの1文なら**動画に無くても足してよい
(新しい事実・主張・メリットを含まないこと)。

## 3. 記事の型

### 序論(冒頭3〜5行が目安)
導入画像(タイトルカードなど)は序論の中、目次の前に置いてよい。経歴の箇条書きなどで5行を超えるときも、結論を先に出せていればよい。
1. (チャンネルの voice.md に定型の自己紹介があれば)自己紹介の固定文
2. テーマと結論の先出し。理由・手順が複数あるなら「〜の3つです」と数を示して番号で並べる(S3)
3. 話者の自己開示(弱み・失敗)が動画にあれば、薄めずに書き出しに使ってよい
4. 目次(`## 目次` + h2 の箇条書き)。note.com 側では `toc()` に置き換わる

### 本論
- テーマごとに h2。各節は「見出し → 画像 → 本文」
- エピソード → そこから得た学び(太字の一文)の順。学びは話者が語ったものの言い換えに限る
- 補足は「ちなみに」で軽く挟んでよい(補足の中身は動画にあるものだけ)

### 結び
- 要点を短くまとめ、読者への呼びかけ(「〜してみてください」「参考になれば幸いです」)で終える(S4)
- **直接相談を促す表現は使わない**: 「一人で悩まず一度話を聞かせてください」「まずはご相談ください」【機械】。
  導線はフッターに任せる。温度感は「もっと情報を見てみようかな」
- 動画に前向き・鼓舞的な発言があれば結びに活かしてよい。無い鼓舞は作らない
- 結びの最後の文に「ぜひ」を使わない。フッター冒頭の「ぜひ」と続いて不自然になる(S12)【機械】
- 動画末尾の「詳しくは概要欄へ」「お問い合わせは DM へ」のような案内は入れない
- 導入・結びの言い回しが記事ごとに似すぎないようにする(同じ型の文を毎回使い回さない。
  定型の自己紹介とフッターは例外で、毎回同じ文にする)

### フッターと注記
チャンネルの `footer.md` を**一字一句そのまま**、結びのあとに置く【機械】。
最後の行は「※本記事の動画内容は、動画撮影時点の情報です。」のような撮影時点の注記(チャンネルの footer.md どおり)。
注記を記事の冒頭に置かない。

## 4. 見出しと構成

- **S1 h2 は3〜6個** 動画の章立て(テロップの①②③、「準備/実践/振り返り」)を h2 にする。
  補足・例外・細目は h3。h2 を7個以上並べると、目次が長くなり構成が見えなくなる【機械】
- 手順・リスト型の記事は `## 1. 〜` の番号付き h2。並列のセクションには番号を付けない
- **S5 時系列のままにしない** 同じ話題が離れた場所に出てくるなら1か所に集める。1見出し1テーマ
- **S6 目次は最後に h2 から作る** 目次の項目と h2 は完全に一致させる【機械】
- **S7 見出しだけで意味が通るか** 逆の意味に読めないか(例:「先輩のやり方を押し通す」)、
  不正確でないか(例:「3つの資格を取った」が実際は2つ)、同じ語を毎回繰り返していないか
- **S8 1段落だけの節は前の節に統合する**
- **S10 インタビューの書き方** 「〜と話してくれました」の連続、
  「〜と思ったか。答えは『思いました』でした」の間接話法は使わない【機械】。
  問いと答えを1つの平叙文にする(例:「今回の経験を経て、ゲストは『早く始めたほうがいい』と改めて思ったそうです。」)
- **S11 数の宣言と項目数を合わせる** 「理由は4つ」と書いたら項目を数える。集計(「合計3つ」)は全部紹介したあとに置く【機械】

## 5. 読みやすさ

note はスマートフォンで読まれる前提。

- **R1 段落は1〜3文・150字目安** 警告線は5文以上か200字超【機械】
- **R2 列挙は箇条書き** 2つ以上の並列(理由・条件・手順・書籍・費用の内訳)は縦に並べる。
  数字の比較は「月額プラン: 1,200円」のように1行1項目にする。シミュレーションは前提を箇条書き→結論の文
- **R3 読点は1文に1個まで** 主語・目的語・副詞の直後に機械的に打たない。
  「私は、新卒1年目で、東京の」→「私は新卒1年目で、東京の」。長い文は読点でつながず分ける。警告線は1文3個【機械】
- **R4 太字は1見出しあたり1〜2か所** 核の一文・読者が「おっ」と思う数字・造語フレーズに絞る。
  少なすぎても(数字や結論が埋もれる)多すぎても(効果が薄れる)よくない。警告線は h2 1つあたり平均3か所超【機械】
- **R5 地の文の一人称はチャンネルの voice.md どおり** ゲストの発言を鉤括弧で引くときはそのまま【機械】
- **R6 一文は60字目安** 「〜のですが、」「〜ていて、」でつながない。警告線は100字【機械】
- **R7 送る前に通読する** 誤字(「頑ななに」)、英単語の混入(「good」)、作業中の文言(「テスト1:32」)を残さない
- ひらがな寄りにする(事→こと、時→とき、様々な→さまざまな)

## 6. 画像

スクショ選びと目チェックの手順は `eye_check.md`。ここには「どこに何を置くか」だけを書く。

- **I1 目が半開きの画像を使わない** 最初から前後0.3秒おきの確認シート(`burst.sh`)で選ぶ。
  判定基準と差し替え手順は `eye_check.md`
- **I2 画像はテロップの内容が出てくる段落の直前に置く** 次の節の内容を先取りしない。
  導入のタイトルカードは目次の前、①②③のタイトルカードはその節の冒頭
- **I3 文脈と合わない場面を選ばない** 特典・SNS の告知、聞き手の相づち(「えーっと…忘れました」)、
  答えが本文に無いクイズの問いだけの場面
- **I4 抽出した画像は全部使うか、フォルダから外す** 本文で使わない画像を残さない【機械】
- **I5 画像の無い文章の塊は300字まで** 超える節には1枚足す(図・画面・テロップのある場面)。
  全体の目安は本文1,000字あたり2〜3枚。長い動画でも30枚を超えるなら、同じ話題の画像を間引く
- **I6 ストック写真を本人の家族の話の節に置かない**
- **I7 目チェックが終わるまで `videos/` の動画を消さない**
- 同じ構図が続いてもテロップが毎回違えばよい。同じ画像を続けて使わない
- 見出し画像(サムネイル)は YouTube のサムネイルをそのまま使う(`00_thumbnail.jpg`)。
  1280:670 へのクロップで文字が切れていないか目で確かめる

## 7. 題名

note の題名は動画のタイトルそのままにしない。次の5つで整える。

1. 金額・期間・件数などの具体的な数字を前に出す
2. 前半20〜25字だけで中身が伝わる語順にする
3. 後半に感情・学びを置く(「〜して分かった続けるコツ」)
4. 30〜40字を目安にし、45字以内【機械】
5. 「無料」を入れない【機械】

動画にない数字や誇張は入れない。半角の「|」は表を壊すので使わない(区切りは全角「｜」)。
題名は管理表の「note記事の名前」列に書き、記事md の1行目も同じにする。予約のときはこの列の題名で送る。

## 8. 書き終えたら(自己チェック)

執筆の直後に、書いた本人が最低限ここまでは確かめる。添削(`critique.md`)は、このあと時間をおいて
読者の目で通読し直す工程で、ここと観点は重なってよい(2回目は、1回目で慣れて見落とした箇所を拾うため)。
lint を通したうえで、目で次を確かめる。

- [ ] 話者が言っていない事実・経験・感情・数字が無い(F1〜F5)
- [ ] 対談なら、エピソードと意見ごとに話者を確かめた(F4)
- [ ] テロップで確かめた固有名詞・数字と、確かめられなかったもの(→ human_review)を分けた
- [ ] 序論に結論、結びに呼びかけ、直接相談の表現なし
- [ ] h2 が3〜6個で、見出しだけで流れが分かる
- [ ] 画像がテロップの内容の直前にあり、全員の目が開いている
- [ ] フッターが footer.md と一字一句同じで、注記が最後

# スクショの選び方と目チェック

動画のスクショは瞬きの瞬間を掴みやすい。添削では半目が最も多く見つかった指摘の一つで、
1記事で何枚も見つかることもある。話者本人が一番気にする点なので、品質の最優先項目として扱う。

**目の判定はスクリプトに任せず、Read で1枚ずつ自分の目で見る。**(時刻の特定には差分などの機械処理を使ってよい)

## 1. 撮るとき(執筆と同時)

1. 字幕の時刻を見て、各節に対応する「良い瞬間」の候補時刻を決める
   - その節の要点のテロップが出ている/紹介対象がはっきり映っている
   - トランジション・移動中の車など無関係なカットではない
   - 告知(SNS・特典)、聞き手の相づち、答えの無いクイズの問いだけの場面ではない(I3)
2. 候補ごとに `scripts/burst.sh <video_id> <scratchpad>/burst_NN.jpg <秒>...` で +0/0.3/0.6/0.9 秒の確認シートを作り、Read で見比べる
3. 一番目が開いているコマを `scripts/extract_shots.sh` で `{images}/{番号}_{短縮}/NN_xxx.jpg` に書き出す。番号は記事内の登場順
   (テストなどで別の場所に出すときは、2つ目の引数に絶対パスを渡す。確認シートの出力先は環境変数 `CHECK_DIR`)
4. 書き出した画像を Read で開いて最終確認する。**確認シートは480px幅なので半目を見落とす**(試験運用で実際に見落とした)。
   人物の顔の部分を実寸で切り出して見る:
   `ffmpeg -y -i NN_xxx.jpg -vf "crop=iw/2:ih/2:iw/4:0" <scratchpad>/face_NN.jpg`(顔の位置に合わせて crop の値を変える)

一覧は `scripts/sheet.sh` で作る(1コマずつ `-ss` で取るので、コマに書かれた時刻が正確で、長い動画でも速い)。
`-vf fps=1/N` で間引く方法は使わない。コマの時刻が最大で約 N/2 秒ずれ(試験運用で別の場面を掴んだ)、
長い AV1 動画ではデコードに10分以上かかる。候補が決まったら、その時刻を `burst.sh` で撮り直して確かめる。
5. 見出し画像は `00_thumbnail.jpg`(YouTube のサムネイル)。1280:670 にクロップしても文字が切れないか確かめる

## 2. 判定基準

| 状態 | 扱い |
|---|---|
| 瞬きの途中・瞼が半分下りている | **差し替える** |
| 迷う(瞳の上半分が瞼で隠れている) | 差し替え候補を探す(半目のまま出すほうがコストが高い) |
| 瞳が上から下まで見えている | 対象外(目が細めでも差し替えない) |
| 伏し目(手元・資料を見ている)で瞳が見える | 対象外 |
| 笑顔で目が細くなっているだけ | 対象外 |
| 横顔・横を見ている目線 | 対象外 |
| もともと目が細い人で、前後のどのコマも同じ表情 | 対象外(記録に残す)。前後のコマと比べて特に閉じていなければ差し替えない |
| ストック写真の人物の演出 | 対象外 |
| 見出し画像(YouTube サムネイル)の演出の表情(目を閉じた顔など) | 対象外(サムネイルは本人側が作ったもの) |

複数人が映っていれば全員を見る。1人でも半目なら対象。テロップ中心で人物が小さい画像も飛ばさない。

## 3. 差し替え(目チェックの工程)

1. 記事の画像を本文の登場順に**全部** Read で開き、一覧にする(例: `03_xxx.jpg: 半開き(左の人物)`)
2. 対象の画像ごとに元の時刻 T を特定する
   - 字幕と、その画像が置かれた段落から絞る
   - 絞れなければ動画を1秒間隔の縮小フレームにして、元画像と近いフレームを探す
3. T の前後約1秒を 0.1〜0.2 秒刻みで scratchpad に切り出す。まず0.3秒おきに大まかに見て、良さそうな付近だけ細かくする
   ```bash
   ffmpeg -y -ss <T-1.0> -t 2.0 -i "{videos}/{video_id}.{ext}" -vf fps=8 -q:v 2 "<scratchpad>/eye_{video_id}_{画像名}/f_%02d.jpg"
   ```
4. 選ぶ条件(上から優先): 全員の目が開いている → **元画像と同じテロップ**が出ている → 口やブレが自然 → 元の時刻に近い
5. 同じテロップの範囲に良いコマが無ければ ±3秒まで広げる。それでも無ければ差し替えず、`human_review` に
   「NN_xxx.jpg: テロップ違いのコマしか無い」と書く(テロップ違いの画像に黙って差し替えない)
6. 元画像を scratchpad に退避し、**同じファイル名で上書き**する(記事mdの参照を変えずに済む)。解像度は元画像に揃える
7. 差し替えた画像をもう一度 Read で開いて確かめる

作業用の候補フレームは `{images}/` に置かない(余計な画像がコミットされる)。
動画本体が無ければ `prep_video.sh` と同じ yt-dlp の指定でダウンロードする。

## 4. 記録

`critiques/{video_id}.md` の状態ブロックに `eye_checked: <日付> (N枚中M枚差し替え)` を書き、
本文の「画像まわりの評価」に、差し替えた画像(元の時刻→新しい時刻)・対象外と判断した画像と理由を残す。
既に下書きがある記事なら、続けて `python3 scripts/note_push.py <番号> --reupload=03_xxx.jpg,05_yyy.jpg` で下書きに反映する
(ファイル名が同じなので、`--reupload` で指定しないと古い画像のURLが使い回される)。
見出し画像(00_thumbnail.jpg)を差し替えたときは `--eyecatch` も付ける。
